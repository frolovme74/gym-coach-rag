# Архитектура

## Путь запроса

```
Браузер (app/static)
   │  POST /api/ask {question}
   ▼
HTTP-сервер (app/server.py)        — валидация, маршрутизация, JSON
   │
   ▼
Пайплайн RAG (app/rag/pipeline.py) — КТ2; сейчас вместо него app/stub.py
   │
   ├─► Предобработка (app/rag/preprocess.py) — нормализация, токены, леммы
   ├─► Индекс BM25 (app/rag/bm25.py)         — топ-k фрагментов
   └─► Клиент LLM (app/llm.py)               — ответ по фрагментам
   │
   ▼
Ответ {answer, found, sources[]} → браузер показывает текст и источники
```

Индекс строится заранее отдельной командой из `data/corpus/` и загружается при старте сервера.

## Компоненты

| Компонент | Файлы | Ответственный (роль) | Состояние |
|---|---|---|---|
| Интерфейс | `app/static/` | Продукт и интерфейс | прототип готов |
| HTTP-сервер и API | `app/server.py` | Интеграция | готов |
| Заглушка ответов | `app/stub.py` | Интеграция | готова, удаляется на КТ2 |
| Предобработка и индекс BM25 | `app/rag/` | BM25 и RAG | КТ2 |
| Клиент LLM и промпт | `app/llm.py` | Интеграция | КТ2 |
| Корпус | `data/corpus/` | BM25 и RAG | КТ2 |
| Benchmark | `benchmark/` | BM25 и RAG | КТ2 |
| Тесты | `tests/` | все | тесты API готовы |

## Принятые решения

**Python 3.11+ и стандартная библиотека для сервера.** `http.server` достаточно для одной страницы и трёх маршрутов; проект запускается одной командой без установки зависимостей. Если понадобятся потоковая выдача ответа или много маршрутов, перейдём на FastAPI — это решение записывается здесь до изменения кода.

**Интерфейс без сборки.** Обычные HTML, CSS и JavaScript: любой участник может открыть и поправить файл, не нужен Node.js.

**Шрифты с Google Fonts.** Unbounded и Manrope подключаются ссылкой в `index.html` — это единственный внешний ресурс интерфейса. Без сети страница работает на системных шрифтах. Если защита будет проходить без интернета, шрифты нужно положить в `app/static/fonts/`.

**Заглушка с тем же контрактом, что и будущий пайплайн.** `app/stub.py` возвращает ответы в формате из `spec/tech/api.md`. На КТ2 сервер переключается на настоящий пайплайн, интерфейс и тесты контракта не меняются. Поле `mode` в ответе (`stub` или `rag`) показывает, что именно отвечало.

**Индекс в памяти, сохраняется в файл.** Корпус небольшой (сотни фрагментов), база данных не нужна. Индекс сериализуется в `data/index/` и в Git не хранится — он воспроизводится из корпуса.

**LLM как сменный клиент.** Провайдер и модель задаются через `.env`; пайплайн зависит только от функции «промпт → текст». Провайдер пока не выбран (открытый вопрос в `spec/product/product.md`).
