# API

Все ответы — JSON в UTF-8. Текущий сервер использует `mode:rag` (поиск и LLM).

## GET /api/health

```json
{"status": "ok", "mode": "rag"}
```

## POST /api/ask

Запрос:

```json
{"question": "Как периодизация силовых тренировок влияет на рост силы?"}
```

`question` — непустая строка до 500 символов.

Ответ 200:

```json
{
  "mode": "rag",
  "found": true,
  "answer_type": "generated",
  "answer": "Текст ответа со ссылками [1].",
  "sources": [
    {"doc_id": "doc_tr_024_001", "topic": "training", "title": "Название документа", "section": "Раздел", "fragment": "Текст фрагмента", "score": 31.35, "url": "https://pubmed.ncbi.nlm.nih.gov/28848690/", "quotes": ["Текст фрагмента"]}
  ]
}
```

`topic` — область документа: `training`, `nutrition`, `supplements` или `recovery`.

Номер в квадратных скобках в `answer` — порядковый номер элемента в `sources`, начиная с 1.

Если в корпусе нет ответа: `found` равно `false`, `sources` пуст, `answer` содержит сообщение об этом.

## POST /api/program

Запрос:

```json
{"goal": "muscle", "level": "beginner", "days": 3, "equipment": "gym"}
```

| Поле | Значения |
|---|---|
| `goal` | `strength`, `muscle`, `endurance` |
| `level` | `beginner`, `intermediate` |
| `days` | целое от 2 до 5 |
| `equipment` | `gym`, `dumbbells` |

Пример структуры успешного ответа 200 (массив `days` сокращён):

```json
{
  "mode": "rag",
  "found": true,
  "title": "Программа на 3 дня в неделю",
  "days": [
    {
      "name": "День 1",
      "exercises": [
        {"name": "Название упражнения из источника", "sets": 2, "reps": "8–12", "citations": [1]}
      ]
    }
  ],
  "note": "Пояснение к программе [1].",
  "sources": [
    {"doc_id": "идентификатор чанка", "topic": "training", "title": "Название документа", "section": "Раздел", "fragment": "Текст фрагмента", "score": 20.0, "url": "", "quotes": ["Текст фрагмента"]}
  ]
}
```

## Ошибки

| Код | Когда | Тело |
|---|---|---|
| 400 | некорректный JSON или значения полей | `{"error": "описание"}` |
| 404 | неизвестный путь | `{"error": "Не найдено"}` |

## Подключение RAG

Health проверяет локальную готовность поиска, без проверки ключа.
Источники дополнены `section` (раздел), `url` (ссылка из manifest или пустая
строка), `quotes` (массив дословных использованных цитат внутри `fragment`).
Номера ссылок назначает сервер в порядке первого использования.
`answer_type` у успешного вопроса: `generated` — пересказ, `extractive` —
дословные отрывки, когда пересказ не прошёл проверку после одной коррекции.
У extractive-ответа есть явное пояснение; неверные предложения модели не
показываются. Некорректные номера источников не допускают и этот вариант.
В упражнениях добавлено `citations` — непустой массив номеров из `sources`.
У программы `found:false` означает `days:[]`, `sources:[]` и объяснение в `note`.
Успешная программа содержит `found:true` и запрошенное число дней.

Дополнительные ошибки: 502 — некорректный/неподтверждённый ответ LLM;
503 — проблемы конфигурации, авторизации, квоты или соединения;
504 — таймаут GigaChat. Тело: `{"error":"безопасное описание","code":"код"}`.
Сбой провайдера не выдаётся за отсутствие информации в корпусе.
Числа и точные цитаты проверяются автоматически; это не доказательство
смысловой корректности ответа.
