# Единая база v4 и практические программы

По требованию пользователя: одна рабочая база, один формат ответа, GigaChat-3-Ultra.
Корпус v4 содержит все 599 прежних чанков и практические памятки проекта.
Памятки подготовлены с помощью ИИ и проверены по перечисленным материалам;
их происхождение сохраняется в manifest. Они не выдаются за текст чужой статьи.
В интерфейсе нет отдельных режимов «по источникам» и «предложение ассистента».

Текущий профиль приложения хранится в `data/corpus-v4/profile.json`; старые
корпуса, профили и отчёты сохраняются как история экспериментов.
Вопросы используют BM25 с приоритетом практической карточки при совпадении
явного шаблона базового вопроса. Это отдельное правило ранжирования, не изменение
формулы BM25; исходный score сохраняется. Карточка должна иметь положительный
BM25 score. Для короткого базового вопроса (до 100 символов) с совпавшим
шаблоном передаются только совпавшие практические карточки: это ограничивает
контекст самим вопросом и уменьшает лишние исследовательские дозировки.
В остальных случаях передаются пять лучших чанков; допустим любой
положительный score. Отсутствие ответа определяет модель по контексту вместе
с прежними ограничениями запрещённых тем. Старый порог не переносится на
расширенный корпус как якобы откалиброванный. Это изменение проверяется отдельно.

Каталог упражнений и диапазоны для программ находятся в manifest тех же
документов корпуса, а их человекочитаемое содержание — в `text`. Для программы
выбираются карточки подходящего оборудования и профиль цели/уровня из этой
же базы. Это фильтрация по проверенным параметрам, не второй корпус.
LLM выбирает идентификаторы упражнений и их порядок. Названия, подходы,
повторения и ссылки формирует сервер по выбранным карточкам. Произвольные
упражнения и неподтверждённые числовые параметры не публикуются.

Есть схемы для 2–5 дней: всё тело, верх/низ, дополнительный облегчённый день.
На уровне новичка 4–5 дней не означают 4–5 тяжёлых тренировок всего тела.
Если LLM возвращает неподходящий список, используется базовый вариант из
тех же карточек и схем. Это рабочий план с настоящими источниками; он не
отмечается как демо. Сбой сети или авторизации остаётся ошибкой провайдера.

Проверяются состав и число дней, отсутствие повторов упражнений внутри дня,
оборудование, покрытие двигательных групп. API остаётся прежним.
Новый корпус требует оценки поиска. Старые qrels не знают новых документов:
сравнение по старым меткам отмечается как диагностика с неполной разметкой.

Манифест с каталогом и шаблонами поиска проверяется по хешу профиля, как и
тексты. При коррекции ответа модель получает прежний JSON вместе с причиной
отклонения, чтобы исправлять конкретную ошибку. Новые карточки короче 300 слов:
каждая содержит законченное правило или небольшой каталог; искусственно
увеличивать их объём ради размера научных чанков не требуется.
