# RAG: текущий поиск и генерация

## Корпус

`data/corpus/documents.json` — единственный актуальный набор. Один документ —
один фрагмент с `doc_id`, `topic`, `source`, `section`, `text`. В базе 632 записи:
599 научных чанков и 33 практические справки проекта. Научные чанки нарезаны
из переводов, обычно 300–600 слов; краткие справки содержат законченный ответ
или каталог и могут быть короче. Происхождение, права и ссылки сохранены в
manifest и `data/sources/`. Полная смысловая вычитка перевода не завершена.

## Предобработка и BM25

Нормализация и токенизация — `preprocess.py`, лемматизация — pymorphy3.
Текущий профиль: лемматизация включена, стоп-слова сохранены, k1=3, b=0.
Самостоятельная реализация BM25 использует postings, TF, DF, длины и avgdl.

BM25 по формулам из методических указаний:

```
IDF(t) = ln(1 + (N − DF(t) + 0.5) / (DF(t) + 0.5))

BM25(q, d) = Σ по t из q:  IDF(t) · TF(t,d)·(k1 + 1) / (TF(t,d) + k1·(1 − b + b·|d|/avgdl))
```


Повторы терма запроса учитываются. Документы без совпадений не попадают в
выдачу; равные score упорядочены по doc_id. Методический пример проверяется
в `tests/test_bm25.py` и `tests/fixtures/bm25_methodical.json` (НИРС, Рубинштейн,
2026, стр. 5–6; повтор «граф» из d1 сохранён согласно последовательности).
BM25 score — не вероятность правильности ответа.

`retrieval.py` добавляет общие понятия периодизации, суперсетов, холодного
погружения и заминки (concept_weight=3, deduplicate_query=false). Затем
`runtime_retrieval.py` поднимает справки с совпавшими шаблонами вопроса,
сохраняя их исходные положительные score. Это уже не чистая сортировка BM25.
У коротких вопросов до 100 символов совпавшие справки из top-5 могут стать
единственным контекстом. Для остальных передаётся top-5.

## Индекс и редактирование

`python -m app.rag.build_index` читает текущие документы, manifest и профиль,
проверяет связность и точные предложения общих дозировок, обновляет хеши и
сохраняет ConceptBM25 в `data/index/bm25.json`. Исторические корпуса не нужны.
Для самостоятельных учебных примеров есть `--plain-bm25 --corpus PATH --output PATH`.
Процедура редактирования описана в `data/corpus/README.md`.

## Генерация и отказы

Пустая выдача, score <= 0 или явно запрещённая тема дают отказ до LLM.
Текущий порог 0 не является откалиброванным классификатором отказов. Старый
порог 13.9097 не перенесён на расширенную базу. Достаточность непустого
контекста оценивает GigaChat. Промпт требует ответа только по контексту.
Цитаты и URL назначает сервер, а не модель. Проверки структуры, цитат, чисел
и отдельных смысловых ограничений не доказывают истинность или логическое
следование всех утверждений. Подробности — `integration.md`.

Программы используют каталог и схемы той же базы, отобранные по параметрам.
Это не BM25-поиск и не произвольная генерация упражнений. Модель выбирает
идентификаторы, сервер проверяет и формирует программу; допустим запасной
базовый вариант. Поэтому у программ нет числового BM25.

## Benchmark

`python -m benchmark.evaluate --output PATH`: текущие qrels, чистый ConceptBM25
и порядок после приоритета справок, Recall@5, Recall@10, MRR по всем предметным
вопросам и по областям, отдельная диагностика score-only отказов.
Основной набор — 24 вопроса и 12 отказов; дополнительные формулировки для
справок — 12 development + 12 check. Разметка неполная, наборы авторские и
регрессионные, не независимая экспертная оценка. Подробности — `benchmark/README.md`.
Первый baseline и финальные результаты сохранены; промежуточные эксперименты
перенесены в архив (`maintenance.md`). Benchmark ничего не обучает.

## Внутренняя проверка по бланку на 15 вопросов

`benchmark/review-15/`: 12 вопросов (по три на область) и 3 ловушки из
существующего набора, без выбора по успешным ответам. Эталоны фиксируются до
генерации и содержат смысловые критерии и дословные свидетельства. Это
внутренний регрессионный прогон, не оценка другой команды и не новые вопросы.
Сохраняются отдельно top-3 ConceptBM25, top-3 после приоритета справок, полный
контекст генерации, ответы и фактические ошибки. В графе документа указано
1 / 2–3 / нет в top-3; релевантный чанк за пределами top-3 и присутствие его
в контексте отмечаются отдельно. Отказы имеют документ «—». E1 — промах top-3,
E2 — плохая нарезка/читаемость, E3 — игнорирование доступного контекста,
E4 — неподтверждённые факты, E5 — ответ вместо отказа при отсутствии ответа,
E6 — спорный эталон. Для HTTP/LLM-сбоя ставится отдельная техническая ошибка,
а не выдуманный E-класс. Правильный отказ обозначается 0 и считается успешным.
Смысловые оценки вносит проверяющий; код не выдаёт наличие цитат за правильность.
