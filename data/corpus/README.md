# Корпус для BM25

Подготовлены 56 обзорных источников — по 14 на каждую область — и 599 чанков.
Это рабочий корпус для индекса и benchmark после целевой редактуры найденных
ошибок. Он ещё не прошёл сплошную смысловую вычитку для публикации.

| Область | Значение `topic` | Чанки |
|---|---|---:|
| Тренировки | `training` | 100 |
| Питание | `nutrition` | 218 |
| Добавки | `supplements` | 161 |
| Восстановление | `recovery` | 120 |

Равное число источников не означает равный объём текста. Разницу не компенсируем
дубликатами: качество поиска предстоит измерить отдельно по каждой области.

## Что индексировать

Только `data/corpus/documents.json`: одна запись — один чанк, пять полей:

```json
{"doc_id": "doc_012", "topic": "nutrition", "source": "Название материала", "section": "Заголовок раздела", "text": "…"}
```

`manifest.json` — служебный файл, не второй корпус. В нём URL, DOI, лицензия,
идентификаторы исходных абзацев, контрольные суммы и глубина проверки.
`reviewed` означает полную проверку входящих абзацев или действующее одобрение
данного чанка; `targeted_checks_passed` — целевую редактуру и отсутствие
неразобранных автоматических замечаний. Второй статус не подтверждает полную
смысловую точность. Таких полностью проверенных чанков сейчас 15 из 599.

## Где редактировать

- `data/processed/ru/<source_id>.json`: удобная сверка `text_en`, неизменного
  `text_ru_machine` и актуального `text_ru`. В `segments` сохранены исходные
  английские и машинные русские предложения, а также `text_ru_edited`.
- `data/review/editorial_edits.json`: полные редакторские переводы абзацев.
  Полный перевод имеет приоритет над правками отдельных предложений.
- `data/review/segment_edits.json`: правки и исключения отдельных предложений.
- `data/review/section_edits.json`: переводы заголовков.
- `data/review/flag_resolutions.json`: разобранные ложные срабатывания проверок
  с объяснением, почему исправлять перевод не требуется.
- `data/review/editorial_scope_exclusions.json`: дополнительные исключения
  по границам проекта. Методологические разделы обзоров также исключаются
  по правилам `scripts/corpus_editorial.py`.

Постоянные правки вносите в редакторские файлы, сохраняя формат существующей
записи. Хеши привязывают решение к оригиналу и машинному переводу; менять их
без повторной сверки нельзя. Ручная правка только `text_ru` или готового чанка
будет перезаписана следующей сборкой. Исходные тексты и машинные версии не удаляются.

## Повторная сборка без модели перевода

Все команды выполняются из корня проекта в ветке `2-rag-benchmark-Murad`:

```bash
python3 -m venv venv/rag
venv/rag/bin/python -m pip install -r requirements-rag.txt
venv/rag/bin/python scripts/corpus_review.py --build
venv/rag/bin/python scripts/corpus_validate.py
venv/rag/bin/python -m unittest discover -s tests -v
```

Эти команды не вызывают модели перевода и не скачивают статьи. Предобработка
использует локальную морфологию `pymorphy3`; это не генеративная модель перевода.
Исходная процедура загрузки и машинного перевода остаётся в `corpus_prepare.py`,
`corpus_model.py`, `corpus_translate.py`, с отдельными зависимостями
`requirements-corpus.txt`. Повторный перевод для редактуры не нужен.

Короткие разделы объединяются с соседним контекстом той же статьи; исходные
заголовки и абзацы сохраняются в manifest. Чанки не перекрываются, содержат
300–600 слов при двух способах подсчёта. Соответствующее число символов не
фиксировано: 300–600 слов не всегда укладываются в 1500–3000 символов.
Исключённые методологические и неподходящие по теме фрагменты остаются в
промежуточных данных, но не индексируются.

## Проверки и происхождение

- `data/sources/registry.json`, `ATTRIBUTION.md`: источники, ссылки, авторы,
  лицензии. Условия CC BY и CC BY-NC действуют также для переводов; корпус
  содержит 8 источников с ограничением некоммерческого использования.
- `data/raw/`: скачанные оригиналы и метаданные, исключены из Git.
- `data/processed/en/`: очищенные английские тексты.
- `data/processed/chunks.draft.json`: историческое имя промежуточного результата
  текущей сборки, сейчас совпадает с подготовленным корпусом. Не индексировать
  одновременно с `documents.json`.
- `data/review/editorial_report.json`, `review_coverage.json`: объём редакторской
  проверки — 192 полных абзаца и 352 решения по предложениям; области могут
  пересекаться, эти числа нельзя складывать как число уникальных абзацев.
- `data/review/paragraph_review_queue.json`, `unchunked.json`: текущие очереди,
  обе пусты. `unchunked.initial.json` сохраняет исходные 91 короткий раздел.
- `data/review/corpus_exclusions.json`, `build_exclusions.json`,
  `section_merges.json`, `editorial_log.json`: причины исключений и журнал сборки.
- `data/review/build_report.json`: готовность к индексации отдельно от публикации.
- `data/review/corpus_validation.json`: проверка схемы, размеров, хешей,
  атрибуции, отсутствия потерь и дубликатов, обработки всех чанков.

Очистка и правки не измеряют Recall@k и MRR. Собственный BM25 реализован;
индекс строится командой `venv/rag/bin/python -m app.rag.build_index`.
В `benchmark/results/2026-11-20-bm25-smoke.json` сохранены проверки учебного
примера и поиска по четырём темам. Метрики учебного примера не оценивают
релевантность нашего корпуса. Полный первый прогон по 24 предметным и 12 отказным запросам сохранён в
`benchmark/results/2026-11-20-baseline.json`; разметка — в `benchmark/judgments.json`.
Следующий этап — сравнение предобработки и подбор параметров. Сервер пока использует заглушку.
