# Gym Coach RAG

Учебный RAG-ассистент персонального тренера: отвечает на вопросы о тренировках,
питании, спортивных добавках и восстановлении, составляет программы и показывает
использованные источники. Проект курса «НИРС 2026: разработка RAG-приложения
с помощью LLM», МГТУ им. Н. Э. Баумана.

## Быстрый запуск

Нужны Python 3.11+ и доступ к GigaChat API. Команды ниже — для macOS/Linux.
При первом скачивании:

```bash
git clone --branch 2-rag-benchmark-Murad https://github.com/frolovme74/gym-coach-rag.git
cd gym-coach-rag
```

Если проект уже есть, перейдите в его папку. На компьютере Мурада:

```bash
cd /Users/murad/projects/GymRAG/gym-coach-rag
git branch --show-current
```

Создайте окружение и установите зависимости (один раз):

```bash
python3 --version
python3 -m venv venv/rag
source venv/rag/bin/activate
python -m ensurepip --upgrade
python -m pip install -r requirements-rag.txt
```

Если `venv/rag` уже существует и работает, достаточно его активировать. При
ошибке `no such file or directory: venv/rag/bin/python` сначала проверьте,
что находитесь в корне проекта, затем создайте окружение командами выше.
Окружение и локальные настройки не передаются через Git.

Настройте GigaChat при первом запуске. Если `.env` уже заполнен, сохраните его.
Чтобы создать файл только при его отсутствии:

```bash
[ -f .env ] || cp .env.example .env
chmod 600 .env
```

Откройте `.env` в редакторе и заполните `GIGACHAT_CREDENTIALS` целым
Authorization key, без `Basic`. Модель — `GigaChat-3-Ultra`, scope —
`GIGACHAT_API_PERS`. Ключ не добавляется в Git. Инструкция получения ключа,
сертификата и проверки доступа: [GigaChat](spec/tech/gigachat.md).
На новом компьютере для настройки из `.env.example` скачайте сертификат:

```bash
mkdir -p .certs
curl --fail --show-error --location --proto '=https' \
  https://gu-st.ru/content/lending/russian_trusted_root_ca_pem.crt \
  --output .certs/russian_trusted_root_ca_pem.crt
python -m app.llm --check
```

Соберите индекс и запустите приложение:

```bash
python -m app.rag.build_index
python -m app
```

Откройте **http://127.0.0.1:8000**. Остановка сервера — `Ctrl+C`.
Если порт занят: `python -m app --port 8001`, адрес будет
http://127.0.0.1:8001. После изменений кода или корпуса перезапускайте сервер.

В следующий раз достаточно:

```bash
cd /Users/murad/projects/GymRAG/gym-coach-rag
source venv/rag/bin/activate
python -m app
```

Без активации можно использовать `venv/rag/bin/python -m app` из корня проекта.
Выйти из окружения: `deactivate`. Если индекса нет, сервер построит его в памяти;
явная сборка сохраняет его для следующих запусков. GigaChat работает через сеть
и расходует квоту аккаунта; локальные тесты и benchmark вызовов LLM не делают.

## Как это работает

В единой базе **632 фрагмента: 599 научных чанков и 33 практические справки
проекта**. Справки подготовлены с помощью ИИ и редакторской проверки;
их происхождение и ссылки указаны в `manifest.json`. Это не 632 научные статьи.

1. Русский вопрос нормализуется и лемматизируется. Собственный BM25 ищет
   совпадения; дополнительный слой учитывает несколько групп близких понятий.
2. Для базовых вопросов правила поднимают подходящие справки в выдаче.
   У короткого вопроса до 100 символов контекст может состоять только из них.
   Поэтому итоговый порядок не всегда совпадает с убыванием BM25 score.
3. GigaChat получает отобранный контекст и формирует утверждения с номерами
   предложений. Поиск в интернете и дообучение модели не выполняются.
4. Сервер проверяет ссылки, цитаты, числа и некоторые ограничения пересказа.
   При неудаче возможны корректирующий запрос, дословные выдержки или отказ.

Программы поддерживают **пять целей, три уровня и пять вариантов оборудования**,
включая тренировки без инвентаря, с резиновыми петлями и одной гирей.
LLM выбирает упражнения для 2–5 дней, сервер проверяет оборудование,
структуру дней и подставляет параметры из карточек. При некорректном выборе
используется базовая схема. Источники здесь отобраны по параметрам, поэтому
вместо BM25 показано «Подобрано под программу».

Модель не обучалась на нашем корпусе. Улучшение базовых ответов объясняется
справками, правилами подбора контекста и генерацией Ultra. Наличие ссылки
не доказывает, что источник подтверждает весь смысл ответа: автоматические
проверки не заменяют смысловую проверку. Полная вычитка перевода не завершена.

## Проверка

После активации окружения:

```bash
python -m unittest discover -s tests -v
python -m benchmark.evaluate --output benchmark/results/my-check.json
```

Для повторного прогона выбирайте новое имя отчёта: существующие результаты
не перезаписываются. Benchmark проверяет поиск, а не качество текста LLM.
Текущий диагностический набор: **Recall@5 = 0.485281, Recall@10 = 0.710833,
MRR = 0.869444**. На проверочных формулировках для целевых справок: 0.833333,
0.833333 и 0.834578. Эти наборы не являются независимой экспертной оценкой.
[Методика и ограничения](benchmark/README.md).

Живая проверка API с GigaChat, расходующая квоту:

```bash
python scripts/rag_smoke.py --live --suite current --output /tmp/gym-live-check.json
```

## Где что лежит

| Путь | Назначение |
|---|---|
| `app/` | сервер, клиент GigaChat, поиск, генерация, интерфейс |
| `data/corpus/documents.json` | единственный текущий корпус; здесь править текст |
| `data/corpus/manifest.json` | происхождение, ссылки, каталог и правила подбора |
| `data/corpus/profile.json` | параметры поиска и контрольные суммы |
| `data/sources/` | реестр первоисточников и атрибуция |
| `data/index/` | локальный индекс, пересоздаётся, не хранится в Git |
| `benchmark/` | актуальные вопросы, разметка, расчёт метрик, ключевые отчёты |
| `tests/` | тесты действующих компонентов и пример из методички |
| `scripts/rag_smoke.py` | живая проверка ответов API |
| `spec/` | продукт, API, архитектура, задачи |

После правки текста или метаданных выполните сборку индекса и проверки.
Если менялись тексты, обновите разметку и её контрольные суммы осмысленно:
benchmark специально отвергает устаревшие свидетельства. Порядок работы с
корпусом — [data/corpus/README.md](data/corpus/README.md).

Промежуточные версии и подготовительные скрипты вынесены из рабочего дерева.
[Что сохранено и где архив](spec/tech/maintenance.md). Запуск больше не зависит
от старых корпусов и моделей перевода. Зависимости перечислены в одном
`requirements-rag.txt`; отдельный дублирующий requirements не нужен.

Ассистент не заменяет врача или очного тренера и не предназначен для лечения.
[Границы продукта](spec/product/product.md), [сценарии](spec/product/scenarios.md),
[задачи команды](spec/tasks.md).
