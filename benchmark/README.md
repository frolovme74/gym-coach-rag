# Benchmark текущего поиска

```bash
python -m benchmark.evaluate --output benchmark/results/new-check.json
```

Команда не вызывает LLM и не требует старых корпусов. `python -m benchmark.run`
также запускает текущую оценку. Учебный базовый BM25 доступен отдельно через
`--plain-bm25` с явно указанным файлом базового индекса.

- `queries.json`: 24 предметных вопроса, по 6 на каждую из четырёх тем, и 12
  запросов на отказ; это многократно использованный диагностический набор.
- `judgments.json`: метки релевантности, цитаты и хеши текстов. Размечены все
  240 позиций текущего top-10 предметных вопросов, но не весь корпус.
- `targeted-queries.json`: 12 development + 12 check, по 3 вопроса на тему
  в каждой части. Цель — конкретная подготовленная справка. Не исчерпывающие qrels.
- `frozen-targeted.json`: отпечаток новых вопросов до первого поиска.
- `annotation-review.json`: последние восемь решений по разметке.
- `run.py`: формулы метрик, проверка разметки и учебная оценка базового BM25.
- `evaluate.py`: оценка профиля приложения и сравнение с финальным отчётом v5.

Recall@k — доля известных релевантных документов вопроса среди первых k;
MRR — средний обратный ранг первого релевантного документа (по полной выдаче,
не ограничен top-10). Метрики усредняются по предметным вопросам, отказы
проверяются отдельно. По областям приводятся отдельные средние.

Текущий диагностический результат: R5=0.485281, R10=0.710833, MRR=0.869444.
Check для целевых справок: R5=R10=0.833333, MRR=0.834578.
В отчёте различаются ConceptBM25 (`raw_bm25`, уже с расширением понятий) и
ранжирование приложения (`runtime`, с приоритетом справок по шаблонам).
Оценка не включает сокращение контекста короткого вопроса и генерацию LLM.

Высокий результат на справках не доказывает качество на произвольных вопросах:
справки и вопросы подготовлены авторами проекта, а прежние ошибки уже
использовались для доработок. Нужен новый внешний тест для независимого вывода.
Неразмеченные фрагменты в метриках считаются нерелевантными. Их появление
помечает отчёт `needs_annotation`. Диагностика score-only отказов не оценивает
правила запрещённых тем и решение GigaChat о достаточности контекста.

Сохранены первый baseline, финальные результаты v5, последний живой прогон и
проверка после очистки. Первый baseline рассчитан на другом корпусе/разметке:
его нельзя сравнивать с текущим как чистый эффект настройки BM25. Финальный
отчёт v5 сохраняет сравнение по старым и обновлённым меткам. Исторические файлы
в отчётах — снимок того запуска; они доступны в архиве из `spec/tech/maintenance.md`.
Новые отчёты не перезаписывают прежние. Benchmark не «дообучает» модель.

## Проверка по учебному бланку

Готовый набор из 15 вопросов, эталоны, живой прогон и заполненный бланк —
[review-15/README.md](review-15/README.md). Это внутренняя смысловая проверка
конечных ответов, отдельная от Recall/MRR; независимую оценку другой команды
она не заменяет.
