# Проверка расширенного корпуса v4

24 предметных вопроса (по 6 на область) и 12 отказных взяты из v3.1.
Это повторно используемый диагностический набор, не новый независимый holdout.
Корпус вырос с 599 до 620 документов. Параметры BM25 не менялись: k1=3, b=0,
лемматизация и прежние понятия. Runtime добавляет приоритет практических
карточек для явно базовых вопросов; на этих 24 вопросах он не сработал.

Прочитаны четыре новых попадания текущего top-10: углеводы вместо гибкости,
упражнение на противоположные руку/ногу вместо суперсетов, общее питание вместо
сравнения диет, недельное расписание вместо активной заминки. Все четыре
нерелевантны. Решения с цитатами — `annotation-review.json`; прежние метки
сохранены, тексты старых документов не изменены. У 24 предметных вопросов
размечены все 240 позиций top-10. Это не исчерпывающая разметка всего корпуса.

| Метрика | v3.1 | v4 | Изменение |
|---|---:|---:|---:|
| Recall@5 | 0.492241 | 0.492241 | 0 |
| Recall@10 | 0.720306 | 0.714354 | −0.005952 |
| MRR | 0.869444 | 0.869444 | 0 |

Добавление документов меняет статистику BM25 и конкуренцию за места в выдаче.
Само по себе оно не гарантирует роста Recall. Качество программ и текстов
Ultra этими метриками не измеряется. Отказ по score в отчёте — вспомогательная
диагностика; приложение использует также фильтр запрещённых тем и LLM.

Воспроизведение из корня репозитория:

```bash
venv/rag/bin/python scripts/build_practical_corpus.py
venv/rag/bin/python -m benchmark.practical_v4 --output /tmp/new-v4-report.json
```

Существующий отчёт не перезаписывается. Если новая выдача содержит unjudged,
команда останавливается и перечисляет пары для чтения и разметки.
