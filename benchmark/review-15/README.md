# Набор под бланк на 15 вопросов

Внутренний прогон от 21.11.2026. Проверена ветка `2-rag-benchmark-Murad`,
исходный commit `959a0ef`. Основная рабочая папка на main не переключалась.
Набор содержит 12 предметных вопросов (по 3 на тему) и 3 ловушки.
Это подмножество прежнего benchmark, а не независимые новые вопросы.

- `questions.json`, `questions.md` — вопросы без ответов и релевантных ID; передавать исполнителю.
- `gold.json` — ожидаемые смысловые пункты, релевантные чанки и цитаты; для проверяющего.
- `frozen.json` — хеши вопросов и эталонов до генерации.
- `run.json` — исходный живой прогон: поиск, контекст, HTTP-ответы и вызовы модели.
- `review.json` — смысловые оценки Codex с объяснениями и хешем оцениваемого прогона.
- `blank.md` — пустой бланк для другой команды.
- `report.md` — заполненный бланк, итоги и полный разбор ответов.

Внешнему исполнителю для слепого прогона нужны только вопросы и
`data/corpus/documents.json`, `manifest.json`, реестр и атрибуция из `data/sources/`.
Эталоны, разметку и наши ответы открывают после его прогона.
Смысловые оценки не считаются экспертной медицинской проверкой первоисточников.

Повторный прогон после установки зависимостей и настройки .env:

```bash
python -m benchmark.review --live --output /tmp/review-15-new.json
```

При использовании отдельной рабочей копии можно передать
`--env-file /полный/путь/к/.env`; сам ключ в команду не вставлять.
Команда расходует квоту GigaChat, делает настоящие запросы через локальный HTTP
API и не перезаписывает предыдущий результат. Семантические оценки не ставятся
кодом автоматически: новый ответ необходимо прочитать и проверить заново.
Правильный отказ отмечается 0 и считается успешным; отказ на предметный вопрос — ×.
Дополнительные причины вне E1–E6 описаны в отчёте, а не подменены другим классом.
