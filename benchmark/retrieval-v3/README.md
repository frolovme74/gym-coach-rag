# Поиск v3: перевод и понятия

Работа трёх агентов на ветке `2-rag-benchmark-Murad`; интеграция не изменена.
Корпус v3 — 599 прежних ID, 21 исправленный перевод. Старые корпус, код BM25,
профиль, разметка и отчёты v1/v2 сохранены; контролируются SHA256 99 файлов.

## Метод

До сравнения зафиксированы четыре варианта: plain, dedup, concepts,
concepts_dedup. Выбор на исправленном development по Recall@5 → Recall@10 → MRR,
при равенстве более простой вариант. Выбран **concepts без удаления повторов**.
Параметры прежние: k1=3, b=0, лемматизация, сохранение стоп-слов; вес понятия 3
зафиксирован заранее. Правила в app/rag/retrieval.py добавляют общие термы понятий
документам и запросам, сохраняя исходные слова. ID и конкретные вопросы в правилах
не используются. Сопоставляются периодизация, суперсеты, холодное погружение и
заминка после нагрузки (post_exercise_cooldown). Заминка и холодная ванна различаются.
Это лексический BM25 с правилами понятий, а не векторная модель.

Диагностические вопросы v2 уже известны и повлияли на разработку правил.
Это проверка исправлений, **не новый независимый holdout**. Development также мал:
новые понятия срабатывают в нём только на вопросе о холодных ваннах.
Метки, вопросы и знаменатели Recall сохранены. В 27 решениях обновлены хеши
изменённых чанков, в 17 — точные цитаты. Одна negative после уточнения nap требует
переоценки и помечена needs_reassessment; она оставлена только для сравнения
на фиксированных метках. Метрики не доказывают корректность всей старой разметки.

## Результат на диагностическом v2

24 предметных вопроса (по 6 на тему), ещё 12 — на отказ.

| Вариант | Recall@5 | Recall@10 | MRR |
|---|---:|---:|---:|
| Текущий v2 | 0.408114 | 0.598530 | 0.766550 |
| Только перевод | 0.415058 | 0.607211 | 0.838640 |
| Только поиск | 0.480336 | 0.723530 | 0.838194 |
| Перевод + поиск v3 | 0.487281 | 0.718322 | 0.869444 |

Первый известный релевантный чанк: периодизация ht02 **27 → 2**,
суперсеты ht05 **47 → 1**, холодные ванны test_re06 **18 → 3**.
Hit@5: 21/24 → 24/24. Precision@10: 0.416667 → 0.458333.
В новом top-10: 110 relevant, 122 non-relevant и **8 unjudged**.
Неполнота разметки сохраняется: unjudged не дают баллов метрикам, но не объявлены
проверенными нерелевантными. Очередь восьми пар сохранена в отчёте errors.
MRR питания немного снизился: 0.763889 → 0.755556.

## Development и ухудшения

| Вариант | Recall@5 | Recall@10 | MRR |
|---|---:|---:|---:|
| Текущий v2 | 0.243629 | 0.347019 | 0.736111 |
| Только перевод | 0.243629 | 0.331929 | 0.736111 |
| Только поиск | 0.243629 | 0.358383 | 0.743056 |
| Перевод + поиск v3 | 0.243629 | 0.343293 | 0.743056 |

Итоговый Recall@10 снизился на 0.003726 (0.37 процентного пункта).
Правки перевода изменили лексическое ранжирование: для tr04 doc_tr_026_019
перешёл с 9 на 12, для nu04 doc_nu_009_008 — с 10 на 11, для re06
 doc_re_031_006 — с 10 на 11. Понятия для этих вопросов не срабатывают.
Вошедшие вместо них чанки частично unjudged, поэтому нельзя считать все замены
ошибочными ответами. Улучшение холодных ванн re05 (R10 2/11 → 5/11)
не компенсировало полностью эти потери. Все изменения по вопросам — в errors JSON.

Глобальное удаление повторов не выбрано: на исправленном development Recall@5
снижается с 0.243629 до 0.239841, остальные приоритетные метрики не улучшаются.
Старый порог 13.909689866544728 дал те же 10/12 правильных и 1/24 ложных отказов
в четырёх сравнениях обоих наборов, но после изменения score **не считается
откалиброванным**. В новом профиле refusal_threshold=null; старое число сохранено
только для диагностики. Политика отказов приложения здесь не реализуется.

## Воспроизведение

Из корня репозитория:

```bash
venv/rag/bin/python -m app.rag.retrieval build --corpus data/corpus-v3/documents.json --output data/index/bm25.v3.json --variant concepts
venv/rag/bin/python -m app.rag.retrieval search --index data/index/bm25.v3.json --query 'Можно ли делать упражнения на противоположные мышцы парами без паузы?' --k 5
venv/rag/bin/python -m benchmark.compare_retrieval --output /private/tmp/retrieval-v3-repeat.json
venv/rag/bin/python -m unittest discover -s tests -v
```

Benchmark запрещает перезапись отчёта, проверяет старые и новые контрольные суммы.
`frozen.json` уже создан; повторная фиксация не требуется. Отдельный профиль:
`benchmark/retrieval-v3/selected_config.json`; сервер его не использует.

Отчёты в `benchmark/results/`: `2026-11-20-retrieval-v3.json`,
`2026-11-20-retrieval-v3-errors.json`, `2026-11-20-retrieval-v3-independent-review.json`.
Все 132 теста проходят. Независимый агент пересчитал 432 сочетания собственной
формулой BM25 и метрики через Fraction, без функций поиска и оценки проекта;
результаты совпали. Предобработка и распознавание понятий общие — их проверяют
отдельные unit-тесты и смысловая проверка. Это независимость расчёта, не данных.
