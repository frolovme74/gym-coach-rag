# Правила репозитория

Правила одинаковы для кодингового агента и для участников команды.

## Порядок работы

Перед изменением кода:

1. Прочитай `spec/product/` и `spec/tech/` — там зафиксированы поведение и решения.
2. Если задача меняет поведение, API или устройство RAG — сначала обнови нужную спецификацию, потом код.
3. Найди задачу в `spec/tasks.md` или добавь её туда.

После изменения кода:

4. Запусти тесты: `python -m unittest discover -s tests -v`.
5. Если менялся поиск или корпус — прогони benchmark и сохрани результат в `benchmark/results/` (с контрольной точки 2).
6. Добавь запись в `CHANGE_HISTORY.md`.
7. Отметь задачу в `spec/tasks.md`.

Код, спецификации и результаты проверки должны соответствовать друг другу. Расхождение — это ошибка, её исправляют в том же изменении.

## Ограничения

- Поисковый индекс BM25 реализуется самостоятельно. Готовые поисковые индексы и библиотеки (`rank_bm25`, Elasticsearch, Whoosh, Lucene и подобные) запрещены. Библиотеку лемматизации использовать можно.
- Ответ LLM строится только по найденным фрагментам и всегда сопровождается источниками. Если в корпусе ответа нет, система говорит об этом, а не выдумывает.
- Границы тем из `spec/product/product.md` («Чего система не делает») обязательны для корпуса, промптов и демонстрационных данных: никаких рецептурных препаратов, стероидов, допинга, лечения и экстремальных диет; дозировки — только из источников.
- Ключи API и другие секреты хранятся только в `.env`, в Git не попадают.
- Новая зависимость добавляется только с обоснованием в `spec/tech/architecture.md`.
- Формат ответов API менять только вместе с `spec/tech/api.md`, тестами и интерфейсом.

## Соглашения

- Язык документации, интерфейса и сообщений коммитов — русский; идентификаторы в коде — английские.
- Python 3.11+, стиль PEP 8.
- Один коммит — одно логическое изменение.
- Папка `materials/` — учебные материалы курса, в Git не хранится.
